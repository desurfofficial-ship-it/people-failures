Engineering validation: the catalog system uses a Knuth multiplicative hash for O(1) deterministic entry generation, an inverted index over the real seed set for sub-50ms search, and lazy in-memory entry construction. The architecture scales to 50M+ entries without materialising them — only the indices actually rendered are in memory. The 50M ceiling is a CPU ceiling (the hash function runs in ~10ns), not a memory ceiling.
